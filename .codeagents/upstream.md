# Перенос исправлений из upstream

[English](upstream.en.md) · [К списку задач](README.md)

1. Проверьте текущую ветку и remotes. Сверьте диапазон upstream с `develop`, [реестром переносов](../diagnostics/upstream-import-status.tsv) и трейлерами `Upstream-Commit:` в истории. При совпадении по смыслу сравните реализацию и тесты. Хеши коммитов меняются при адаптации.
2. Разделите смешанный diff на независимые исправления. Сохраняйте оригинальный баланс, изменения нашего форка и совместимость. Сомнительное игровое изменение сверяйте с оригинальной игрой. Отдельно отмечайте уже реализованные части, принятые исправления и осознанные исключения.
3. Для каждого исправления получите ожидаемый RED на штатной реализации, затем GREEN после правки. Ошибка сборки не подтверждает игровой дефект. Проверьте связанные платформы, сериализацию, кампанию или сеть в зависимости от затронутого кода.
4. При коммите помещайте тест и фикс в один самостоятельный коммит с трейлером `Upstream-Commit: <публичный URL коммита>`. Обновите реестр переносов. Если пользователь попросил push, отправьте согласованные изменения и проверьте удалённую ветку.
