# Эталон занятия пулемёта до переноса оплаты на завершение

`cannon-entry-before-deferred.bin` — один полный нативный граф игры, мира,
персонажа, игрового пулемёта и работающего CExecCannon. Создан настоящим
CExecCannon::Run до изменения момента оплаты, без имитации старого алгоритма.
Это тестовый контейнер CStructureSaver, без заголовка файлового save-slot.

- Размер: 1182638 байт (около1.13 МиБ).
- SHA256: `05c3307daa22fbb9799b1acd68e73a23db82ffb3f6b943ab43bf25e4aca549d1`.
- Производственные исходники: `de0bccf65151b90f254f29a2f4c51a7d1f76aed4`.
- База game.db, SHA256: `314d7aa9e6339f0e6826bf2a0c71fdad992aec1d6074a2ed763a6f6fa62d62df`.
- Генератор: WriteLegacyCannonEntryFixture в UpstreamBugTests.cpp,
  режим `cannon-entry-legacy-write <game.db> <res> <output>`.
- Корневые теги:1 игра,2 мир,3 персонаж,4 пулемёт,5 исполнитель,
  6 уже оплаченные AP,7 исходная стоимость подхода.

Миссия810/seed123, persona838, личное оружие30, пулемёт65/DShK12.7mm.
После реального Run: AP46->42, стоимость4; RPG cannon item, occupant и
состояние пулемётчика уже установлены, но исполнитель ещё RUNNING и держит
настоящий action counter. Нативный клип3947 длится833мс. Генератор проверяет
эту старую фазу до открытия выходного файла и отказывается писать новый
эталон, если Run больше не выполняет прежнюю оплату/занятие.

UpstreamCannonEntryLegacy читает неизменённый граф штатным CStructureSaver,
восстанавливает runtime caches мира и завершает подход: AP42->42, occupant/
RPG item/state сохраняются. Тест проходит на Windows и Linux. Отдельный
UpstreamCannonEntryCompletion проверяет уже новую неоплаченную фазу,
независимый полный граф после восстановления и оплату ровно на completion.

Это проверка нативного графа и action callback; загрузка через интерфейс
файлового save-slot и полностью исполненный игровой кадр не заявляются.
Отдельной копии исходников/игры/сборки нет; эталон хранится один раз.
