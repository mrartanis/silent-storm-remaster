# Эталон прежней карты главы без мира

`chapter-before-world-init.bin` — полный нативный граф CGlobalGame и
CChapterMap, созданный настоящим CICBeginChapter. Это тестовый контейнер
с корневыми тегами 2 (игра) и 3 (карта главы), без заголовка файлового save-slot.

- Размер: 132791 байт.
- SHA-256: `2f1062e4bcc316d2246c3723c80f7fdb69181b9e89eaf6daf9eeb145a4366586`.
- Исторический Main/iChapterMap.cpp:
  `f79b0b89604a624f3801330109bb2b94bd79cc2d`.
- Остальные производственные исходники при генерации:
  `fb97e31ce2c85bdb041117f96d586c9e9fc4a51d`.
- Исходная база game.db, SHA-256:
  `314d7aa9e6339f0e6826bf2a0c71fdad992aec1d6074a2ed763a6f6fa62d62df`.
- Генератор: WriteLegacyChapterFixture в UpstreamBugTests.cpp,
  режим `chapter-legacy-fixture-write <game.db> <res> <output>`.

Генератор выбирает первую карту главы с фоном, создаёт игру и игрока с
бойцом 54, открывает главу через настоящий CICBeginChapter и задаёт цель
маршрута (113,227). Перед записью проверяет историческую форму: нет мира,
рендера, сцены, активного player tracker и mission desktop, но настоящий
интерфейс и его собственная звуковая сцена присутствуют.

Для генерации только исторический iChapterMap.cpp временно читался из Git
в текущий checkout. Использована существующая Windows x64-сборка;
после записи исходник восстановлен к HEAD, та же сборка пересобрана и
подтверждён runtime RED. Отдельной копии игры, исходников или сборки нет.
Эталон занимает около 130 КиБ и хранится один раз для регрессии совместимости.

LegacyChapterWorldMigration читает этот граф штатным CStructureSaver и
вызывает тот же OnSnapshotRestored, что используют CICLoad и CICLoadFile.
Проверяются сохранение интерфейса/курсора/маршрута/RPG-объектов, создание
недостающего мира и повторное сохранение полноценного графа. Для нового
графа повторный hook не должен создавать мир заново или сбрасывать его время.
Фактическая загрузка через файловый save-slot этим тестом не заявляется.
