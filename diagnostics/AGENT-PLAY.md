# Игра с LLM-агентом

Режим включается только параметрами бинарника. Меню, кампания, одиночные
сохранения, баланс, AP, попадания и сетевой протокол не менялись.

## Навык в репозитории и установка

Навык хранится в
[`.agents/skills/silent-storm-play/SKILL.md`](../.agents/skills/silent-storm-play/SKILL.md),
запускатель — в [`tools/agent_play.py`](../tools/agent_play.py),
игровой канал — в [`Game/AgentPlay.cpp`](../Game/AgentPlay.cpp).
Агент, работающий с этим checkout, может прочитать навык непосредственно
из репозитория. Для установки навыка в пользовательский каталог Codex
выполните из корня репозитория:

```powershell
$skillsRoot = if ($env:CODEX_HOME) {
  Join-Path $env:CODEX_HOME 'skills'
} else {
  Join-Path $HOME '.codex/skills'
}
$skillDirectory = Join-Path $skillsRoot 'silent-storm-play'
New-Item -ItemType Directory -Path $skillDirectory -Force | Out-Null
Copy-Item -LiteralPath '.agents/skills/silent-storm-play/SKILL.md' `
  -Destination (Join-Path $skillDirectory 'SKILL.md') -Force
```

Навык предназначен для запроса «поиграем вдвоём в Silent Storm».
Приведённые в нём пути `G:\SS\...` — проверенные локальные примеры;
для другого компьютера агент использует расположение своего checkout,
подготовленного движка и игровых данных.

## Сборка инструментов и подготовка движка

Окружение для `tools/agent_play.py` и `diagnostics/AgentPlayTests.py`:

- Python 3.11+;
- pip-зависимости: отсутствуют, используется стандартная библиотека Python.

Из корня репозитория в PowerShell:

```powershell
python -m venv .venv-agent
.\.venv-agent\Scripts\Activate.ps1
python tools/agent_play.py --help
```

Дальнейшие команды `python` выполняются в этом окружении. Если активация
не используется, вызывайте `.\.venv-agent\Scripts\python.exe` напрямую.

**C++-канал собирается внутри обычной цели `Game`**, отдельного сервера или
проекта для него нет. Для первой сборки установите зависимости и выполните
полную конфигурацию CMake по разделу
[Windows x64 в README](../README.md#windows-x64). Нужны MSVC v143/Windows SDK,
SDL3, bgfx и остальные зависимости обычного движка. Для существующего
настроенного каталога сборки, из корня checkout:

```powershell
# Использовать уже подготовленный HD-пак, не запускать его установку при сборке.
cmake -S . -B build -DS2_BUILD_HD_TEXTURES=OFF
cmake --build build --config Release --target Game zlib --parallel
```

Для отладочной сборки замените `Release` на `RelWithDebInfo` и передайте
запускателю `build/RelWithDebInfo/Game.exe`. Рядом с EXE должны лежать
`network-version.txt`, актуальные DLL и `fonts` из той же сборки; их копируют
обычные CMake-правила движка. Параметры native media из README обеспечивают
звук, музыку и ролики. Старый бинарник без `Game/AgentPlay.cpp` не сможет
обслуживать этот канал — после обновления исходников пересоберите `Game`.

`--package` указывает на полную копию оригинальных данных с `game.db`,
`tree.mma`, `cfg`, `res` и `scripts`; `--exe` — на новый движок.
Текущий запускатель также ожидает готовый HD-пак в `PACKAGE/res-hd` или
`data/res-hd` checkout. Если его ещё нет, подготовьте замороженный runtime-архив
по [data/README.md](../data/README.md), без генерации или пересборки PNG.
Настройка `S2_BUILD_HD_TEXTURES=OFF` сама этот пак не устанавливает.

Пример с обычными путями после сборки:

```powershell
python tools/agent_play.py start `
  --package C:/Games/SilentStorm-test `
  --exe build/Release/Game.exe `
  --output C:/s2-runs/agent-play-first `
  --squad 1
```

## Быстрый запуск на рабочем компьютере

```powershell
python tools/agent_play.py start `
  --package G:\SS\lab\baseline `
  --exe G:\SS\lab\build-x64-stage4\RelWithDebInfo\Game.exe `
  --output G:\SS\lab\agent-play-my-match `
  --squad 1
```

Каталог результата должен быть новым. Запускатель создаёт изолированные
каталоги `host`/`client`, отдельные `S2_USER_DATA_DIR`, соединяет обе игры
через TCP/IPv4 и возвращает пути доступа к игрокам. Окно хоста видит человек,
клиент скрыт и управляется агентом. `--human-side client` меняет стороны;
`--hidden` скрывает оба окна для матча агентов. `--squad 1..6` задаёт размер
отрядов, `--map` выбирает существующий вариант случайного столкновения.
Проверка ресурсов при запуске может занимать несколько минут.

```powershell
python tools/agent_play.py call --player G:\SS\lab\agent-play-my-match\client-player.json observe
python tools/agent_play.py call --player G:\SS\lab\agent-play-my-match\client-player.json screenshot
python tools/agent_play.py call --player G:\SS\lab\agent-play-my-match\client-player.json --wait-turn 20 observe
python tools/agent_play.py call --player G:\SS\lab\agent-play-my-match\client-player.json move 0 20 30
python tools/agent_play.py close --session G:\SS\lab\agent-play-my-match\session.json
```

В `SKILL.md` описаны координаты, команды, коды результатов и игровой цикл.
Инструменты включают наблюдение, PNG-скриншоты, движение, поворот, стрельбу,
предпросмотр AP/шанса попадания, перезарядку, позы, скрытность, рюкзак,
экипировку, лечение, продолжение/остановку действия, передачу хода, камеру,
этажи и обычные клики по существующему интерфейсу/объектам.

## Устройство и границы

`Game/AgentPlay.cpp` обслуживает отдельный запрос-ответ на игровом потоке:
атомарный `_agent_request.txt` → `_agent_response.json`. Канал активен только
при `-agent-play`. Команда начинается с числового request ID; ответ JSON
возвращает тот же ID, `ok` и наблюдение. `quit` предназначен запускателю.

Пример непосредственного запуска подготовленной пары бинарников:

```text
host/Game.exe -agent-play -net-host 17890 -net-squad 1 -windowed -1024 -cfg agent.cfg
client/Game.exe -agent-play -agent-hidden -net-connect 127.0.0.1 17890 -windowed -1024 -cfg agent.cfg
```

Рабочие каталоги и `S2_USER_DATA_DIR` у экземпляров должны различаться.
`-agent-play` поддерживает фоновые игровые кадры, не включая `-harness`.
Совмещение с `-harness`, `-loadslot`, `-load`, `-noai` отклоняется.
`-agent-hidden` сохраняет SDL/bgfx-рендер и обычную видимость: это скрытый
графический клиент, которому нужен GPU/графический backend, а не сервер без
рендерера. Авторитетный сервер совмещён с экземпляром хоста, как в обычной сети.

В Python нет сторонних зависимостей. Запускатель сейчас предназначен для
Windows; C++-канал использует переносимые игровые API, но запуск на Linux/macOS
в этой работе не проверялся. Готовый HD-пак подключается повторно, без генерации.

HTTP-посредник слушает только `127.0.0.1`; у сторон разные случайные capability
токены. POST на endpoint из `*-player.json` принимает:

```json
{"command":"preview_attack 0 1","settle":true,"wait_turn":0}
```

Он последовательно выполняет запросы каждой стороны, ограничивает словарь
команд, при необходимости ждёт окончания анимации и сохраняет отдельный
транскрипт. Административный `session.json` используется только координатором
для завершения своей пары процессов.

Наблюдение перечисляет **собственный** отряд и его инвентарь. Чужие бойцы
берутся исключительно из `IPlayer::GetVisible`; их инвентарь, AP, приказы,
реестр и скрытые позиции не возвращаются. HP врага подчиняется штатному
`GetEnemyUnitInfo` и соответствующим перкам. Идентификатор контакта локален
для игрока. Перед атакой его видимость проверяется заново; исчезнувшая цель
не разрешается через сохранённую ссылку. Стрельба по запомненной точке доступна
как в обычной игре. Все действия идут через `CMission::Command` и существующую
проверку сетевых команд; предпросмотр использует штатный `CanDoCommand`.
Камера использует обычные границы перемещения/приближения.

Это ограничение игрового API, **не изоляция процесса от злонамеренного локального
кода**: сетевой CPU-граф остаётся в процессе, как и раньше. Навык запрещает
играющему агенту читать память, сейвы, исходники, debug/world-дампы и чужие
данные. Для настоящего недоверенного клиента нужна отдельная задача по
серверной фильтрации репликации и системной изоляции.
